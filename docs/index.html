trianglewins

Constrained triangulation in R: the same inputs through every backend, judged by code that belongs to none of them. Backends are laridae (CGAL), cdtr (CDT), trowel (spade) and RTriangle (Triangle).

Survey of R triangulation packages

About 35 packages classified by algorithm (ear cutting, Delaunay, constrained, quality refinement), upstream library, input form, constraints and output control, with a lineage table and a capability matrix.

Benchmark at scale

Times, memory and mesh quality on geoBoundaries country polygons, from 23 thousand to 6.8 million vertices: constrained, area and quality refinement, point Delaunay, and edits to a live mesh.

Choosing a package

For R users: what to try for each kind of problem, from filling polygons for drawing to quality meshes, statistical meshes and editable meshes. CRAN packages first.

Roadmap for R and Python

Which development steps help most, the CRAN order for cdtr, laridae and trowel with what blocks each, the Python landscape, and what we can offer other package authors.

On dimension: these pages keep geometric dimension (coordinates per vertex: xy, xyz, xyzt) apart from topological dimension (0 point, 1 segment, 2 triangle, 3 tetrahedron). The meshes here are triangles (topological dimension 2) built from xy coordinates.
